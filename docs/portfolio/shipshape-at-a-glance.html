Shipshape

Most project tools track what you are doing. Shipshape also tracks what "done" is supposed to mean — written once, applied to every project you own — and turns whatever falls short into cards on that project's board.

How to run and sign in

  1. The brand page above needs nothing — it is a standalone page with no build step, so the design can be judged before any of the software is installed.
  2. To run the app: pnpm install, then pnpm db:push to create the schema and pnpm db:seed to load the built-in standards and a demo portfolio.
  3. pnpm dev, then open localhost:3000 and enter the email address the seed created.
  4. There is no password. The app emails you a one-time sign-in link — and with no mail provider configured it prints the link to the terminal instead, so local development works with nothing to set up.
  5. Sign-in is invite-only by design: a link is only ever issued to an address that already has an account, so the form cannot be used to create one.
  6. Want just the domain logic? pnpm test runs all 49 tests with no install at all — the core package has zero dependencies.

That last point is deliberate. The scoring rules are the part worth reviewing, so they were built to be reviewable in isolation — no database, no environment, no server.

The question it answers

Not "how is this project doing". The question is "which of the eight things we own still cannot take a payment" — and answering that needs one standard held across a whole portfolio, not eight separate opinions.

1. Write the standard once

A list of things that must be true before something is ready — each with a weight, and guidance saying what "met" actually looks like.

2. Apply it to everything

Every project gets scored against the same list, so the answers can be lined up next to each other and actually compared.

3. The gaps become work

Each thing that isn't met turns into a card on that project's board, carrying the guidance as its acceptance criteria.

How a project is graded

ReadyEverything required is met, and the weighted score clears the bar.
On trackScoring well, with nothing required outstanding.
At riskEnough gaps that the date is no longer safe.
BlockedSomething marked required is not met. No score can rescue this.
WaivedDeliberately excused, with a reason recorded — not silently skipped.

All the arithmetic is done in whole numbers — weights in points, credit in hundredths of a percent — so the same portfolio never shows two slightly different percentages depending on which screen you are looking at.

What I built

  • The domain, the schema, the app and the design system — four packages in one repository, written from an empty directory.
  • Made the scoring reviewable on its own. The rules live in a package with zero dependencies and zero I/O, so all 49 tests run with nothing installed — which is what let the hard part be finished and verified before the database existed.
  • Refused to let a criterion exist without guidance. If you cannot write down what "met" looks like, it is not ready to be scored — so guidance is a required field, not an optional note.
  • Kept the public brand page honest without leaking. The real portfolio page is scored against real projects; a build script swaps in illustrative data and refuses to write the file if any real project name survives.
  • Left signup out on purpose. Sign-in is invite-only, because an open passwordless form on a product with no billing is a spam magnet rather than a growth feature.
